# SYSU SNAT v2 架构

实现入口为 `snat/v2`，以一个架构相关的 `sysu-snat` 软件包交付控制器、C 辅助程序、配置与 LuCI。运行参数及验收见[使用说明](sysu-snat.md)和[验收记录](sysu-snat-v2-validation.md)。

## 1. 职责与系统边界

插件维护 IPv4、IPv6 每族固定五个可接收新连接的扩展源地址。主 WAN 由 OpenWrt 维护，不计入扩展池。插件不负责认证、netifd、主默认路由、MAC、DNS 上游、DHCP 分配或代理配置。

允许的写入范围：

- 自己创建并记录的 `/32`、`/128` 别名，内核协议标记为 186。
- 两族私有 `sysu_snat_v2_4/6` 表及短时探测表，不执行全局防火墙 reload。
- 精确匹配退出成员地址的 conntrack，其他成员的连接不清理。
- 有所有权记录的 IPv6 LAN/Tailscale 源默认路由，以及表 40960、优先级 32000 的共享 `/64` 回程；不替换原生默认路由。
- 可选 dnsmasq WAN 监听排除，仅管理 `sysu_snat_notinterface` 记录的自身新增条目。实际监听列表改变时重载 DNS 配置，不启动原来停止的 DNS 服务。

ARP 无响应、DAD 与 HTTPS 成功不代表获得 DHCP 租约或上游授权。后段加权依据用户长期观察，不据单次 ARP 扫描推断学校 DHCP 分配顺序。

## 2. 单控制器与有界任务

procd 仅登记 `controller`。`net-helper supervise` 独占持锁，启动 ucode 控制器，退出时回收其任务组。锁不传入工作进程；子任务不能在控制器死亡后阻碍新实例取得锁。procd 每三秒尝试恢复，不因累计次数耗尽永久停止。

控制器每秒协调，IPv4、IPv6 各允许一个有界网络任务，两族互不阻塞。C `run` 辅助程序提供超时与父进程死亡回收；探测期间事件循环继续处理冲突、成员过期、规则续期和状态发布。

优先级为退出/冲突、即将到期的证据、普通健康检查及补位。缺额时每两次普通健康任务让出一次发现机会，防止普通检查持续饿死补位。实际探索仍受连续令牌、容量、短退避和协议限速约束。

普通配置应用更新代次，迟到结果因 generation/epoch 不匹配而隔离；仅目标改变时撤销原目标的验证证据。日志或出口策略变化不使整个池重新构建。

## 3. 网络依据与所有权

`backend.context()` 从 netifd 获取当前原生地址及 WAN/LAN 设备，从内核读取网关。手动主地址必须是当前可用原生地址，不能把接口上任意别名当成主地址。

IPv4 支持与 LAN 不重叠的私有 WAN `/8`–`/30`。IPv6 支持全球 `/64`、链路本地网关和 LAN ULA `/48`–`/64`。不宣称支持任意 PPPoE、PD、多 WAN 或端口映射场景。

拓扑指纹包括设备、主地址/前缀、网关及 LAN 范围，不包括别名、计数器和自然递减的租期。真正拓扑变化只使受影响族退出；同前缀续租更新别名期限，不因正常续租整池重建。

绑定前原子保存创建意图，成功后保存创建结果。恢复时核对成员身份、内核对象和协议标记；不能证明归属时阻止新发现。删除前重新查询 netifd，保护已经成为原生地址的对象。

IPv6 别名采用 `preferred_lft 0`，普通未绑定连接继续优先使用原生源地址。别名有效期受当前前缀有效期约束，续租后按当前期限维护，DAD 未完成或失败的地址不准入。

## 4. 选址、容量与连续预算

IPv4 在实际 WAN 子网分为四个等大区域，权重为 `1:2:4:8`。先抽区域，再在剩余地址中均匀无放回取样，使用内核随机源与拒绝取模偏差。按排名跳过排除项，不为大子网建立稠密数组。

排除主地址、网关、子网边界、本机地址、管理员候选排除项、现存成员及冷却项。IPv6 在当前 `/64` 内随机生成接口标识，排除原生地址及现存成员。

| 限额 | 当前值 |
| --- | --- |
| 每族新连接目标 | 5，LuCI 无修改入口 |
| 每族总绑定上限 | 8，包含候选、暂留和退出成员 |
| 每族临时候选上限 | 2，实际网络任务按族串行 |
| 单轮发现 | 32 次尝试或 120 秒 |
| 无工作成员退避 | 2/5/10 秒，10 秒封顶 |
| 有工作成员退避 | 5/10/15 秒，15 秒封顶 |
| 每族连续预算 | 16 个新候选/分钟，突发 8 |
| 共享 WAN 连续预算 | 双栈合计 24 个/分钟，突发 8 |
| 原生参照未知时探索 | 每 30 秒最多一次，仍要求双目标成功才准入 |

令牌按连续时间恢复，不存在整小时耗尽停试。局部准入或旧成员恢复立即重置退避。满池停止发现，健康成员没有强制轮换期限。

IPv4 ARP Probe 按 RFC 5227 初始时序执行，确认后发送公告并持续被动监听。真实冲突退让并冷却 24 小时，不争夺地址；十次冲突后至少等待 60 秒。明确源不可用的候选冷却约十分钟，参照未知仅短冷却，不升级为长期冲突记录。冷却和事件有界，不通过提前删除未过期冲突记录腾空间。

## 5. 证据与成员状态

每次验证至少两个独立 HTTPS 主机，支持第三目标。解析后固定对端 IP，并绑定实际设备与源地址；检查 TLS、HTTP 2xx、实际对端以及 conntrack 原始/回复元组。探测规则仅匹配 root GID、指定源端口、目标 IP/端口；不把代理成功算成候选直连成功。

失败时使用原生源及其他健康成员交叉参照，区分目标故障、上游未知和源不可用。探测连接有独立 conntrack 标记，不计入业务排空；直接使用池地址的真实业务仍计入。

| 状态 | 含义与处理 |
| --- | --- |
| validating / ready | 候选绑定并验证，双目标合格后才能准入 |
| active | 证据有效，参与新连接；单目标仍可达时保留部分工作能力并改善 |
| observing | 首次双目标失败，保留现有证据并快速复验 |
| suspect | 连续第二次失败，暂停新分配，允许复验恢复与补位 |
| held | 证据过期但上游情况未知，保留绑定，不参与新连接 |
| draining | 已有替代成员，不再接收新连接，等待旧业务退出 |
| retiring | 确认失效、冲突、缺失或拓扑变化，精确清理 |

健康检查间隔 15–60 秒，默认 60 秒；正面证据最长 180 秒。连续第三次经参照确认的失败退出；冲突和地址缺失立即撤出选择。suspect/held 恢复须经过两次正面检查。

计划换新先验证替代者，再替换新连接映射，每族按一个退出窗口推进。旧成员业务数为零或达到 300 秒上限后精确撤销连接、删除地址。恢复成员遇到满池不会踢掉健康替代者；退出窗口忙时暂留等待。

## 6. 规则、映射与失联回退

五种策略为 original、primary、random、host、endpoint，按 LAN、代理 GID、Tailscale 和协议分别设置。例外从上到下首条命中，支持地址族、来源/目的范围和端口。访问 WAN 本地网段不转换。

random 在可用成员中等概率选择，选址权重不影响已入池成员的流量比例。host/endpoint 统一采用 1024 桶 rendezvous 映射。每族保持固定随机种子，成员地址及桶号经 FNV-1a 与 SplitMix64 混合取最高分，同分按地址排序。散列只负责分布，不承担密码学功能。endpoint 的桶输入仅包含来源地址与 UDP 来源端口。

成员变化只改变必要桶，已有 conntrack 不随规则更新迁移；不承诺源端口保持不变。

每族业务表同时包含协调器 90 秒租期和成员最长 180 秒证据租期。选择槽位过期后按配置退回原生主地址或原出口，不依赖用户态及时运行。规则提交使用单个 nft 事务，并在提交前执行 `nft -c`。

控制器约每十秒结构化回读私有表及必要路由，忽略句柄、计数器和自然递减的到期值，比较实际语义；漂移时仅修复自身对象。正常续期只更新超时集合，保留计数器。

## 7. 配置、DNS 与管理面

UCI 只保存用户配置；`config.uc` 和 `validate.uc` 统一校验地址、CIDR、模式、端口、HTTPS 目标和原生主地址，再原子发布仅含 `policy.json` 的不可变代次。无效配置保留原运行配置，不提交空 procd 实例。

DNS 保护根据当前配置和仍绑定成员的 resource context 维护排除项。存在未应用 DHCP 修改或共享 WAN/LAN 设备时拒绝误改；重载失败恢复自身变更。关闭或停止时只撤回自己新增的条目，保留管理员原设置。

RPC 只公开 status/members/events/operation/logs 与固定 control 动作，状态读取不主动探测。管理动作先返回 operation_id，再查询 pending/running/completed/failed/interrupted；重复动作合并，不把 accepted 当成完成。

LuCI 沿用主题以支持深色模式，分别显示原生地址、绑定/可选/严格合格数量、成员状态、验证时间和操作结果。不开放数量、预算、权重或并发调参。

## 8. 状态恢复与停止

`/var/run/sysu-snat/v2` 权限为 0700。JSON 原子发布，保存 boot_id、代次、所有权、创建意图、上一有效状态、令牌与冲突预算。核心状态损坏时恢复上一快照；未知意图拒绝认领。

控制器进程退出保留数据面，显式 stop 才逐项释放插件资源。清理未确认成功时保留记录，供后续恢复；不清空全局 conntrack、地址或路由。服务启用与临时停止分开，禁用并应用才取消自启动。

事件环上限 512 条，单条描述最长 512 字节；冷却容量上限 4096，容量不足时暂停发现而非争用已知冲突地址。外部 ARP 声明不是认证证据，不能据此宣称解决二层欺骗。

## 9. 验证

核心决策、运行规则、检查点、双栈配置校验、配置发布、DNS 所有权和 LuCI 权限均有回归。ARP 模拟测试只在新建空网络空间运行，实机检查使用 `tests/live.py`。正式包由 OpenWrt SDK 生成，实机逐文件核对；具体版本、测试结果和未覆盖范围记录在验收文档。
