# SYSU 认证插件

面向 OpenWrt 的中山大学有线校园网认证。LuCI 的“启用”同时管理常驻认证和开机启动；地址、DHCP、DNS、路由仍由现有网络接口配置管理。

## 协议与依据

参考材料是桌面 reconstruction 的有线认证代码。为补齐静态重建缺口，另核对了[学校提供的 Linux 客户端](https://inc.sysu.edu.cn/service/wired-network-access)中 x64/rjsupplicant 的原始指令，SHA-256 为 196705b737ac57a166497df2b26e7a3d9356c4f6e86b2df893af1c33ec778459。

本次校园网实测纠正了重建材料中的两项错误：

- EAP-MD5 使用 MD5(id || password || challenge)。用户名作为摘要输入时，服务端返回“用户不存在或者密码错误”。
- RG 扩展放在标准 EAP/EAPOL 长度之外。将扩展计入长度时，服务端在 Identity 阶段即拒绝认证。

普通 NAS 的身份响应、RG TLV、RADIUS 密码字段和 Vz 五种模式均有离线测试。锐捷 NAS 仍使用已有私有属性编码器；参考重建本身未补齐该分支，不能宣称与官方客户端完全等价。

原始二进制的关键定位点：

| 路径 | 定位与验证 |
| --- | --- |
| SAM 周期握手 | HandshakeToSAM 0x437740、PostPacketNoResponse 0x4416a4；确认正常 Hello 不等待 ACK |
| 密钥与 IV | ReadRGVendorSeg 0x457b73 / 0x457c1e；确认 RC4 解码，抓包摘要与 DES 解密结果交叉验证 |
| ACK | ResponseSender 0x47962c；42 字节，核对版本、序号、事务、标记与摘要 |
| UDP 端口 | 追到最终发包参数并以抓包确认源 138、目的 53，避免把中间结构字段名称当作线格式 |

## 会话维护

服务端参数既可能在最后一轮 MD5 请求中，也可能随 Success 或长度外扩展到达，均须保留到认证成功后使用。

当前校园网使用 SAM：服务端下发 120 秒维护间隔、服务器地址、端口、RC4 包装的 DES 密钥和 IV。原始客户端确认的线格式包括：

- 客户端源端口来自 0x6e，服务器目的端口来自 0x5a；本次为 UDP 138 → 53。
- 42 字节包头之后是 DES-CBC 密文，不发送重建代码中假定的 16 字节零尾。
- MD5 覆盖清空摘要后的包头、密文、key 和 IV；序号、事务号、UTC 和分片标记分别校验。
- 用户信息在建立会话或地址改变时上报。周期维护使用原版的无 ACK SAM Handshake，每周期仅发一次。额外每 600–1800 秒发送一次有 ACK 的用户信息确认，用于检测静默失效；这是增强策略，当前间隔为 600 秒。
- 接受协商上限内的 v1/v2 服务端回应。通过端点、摘要与事务校验的 v1 回应会使后续发送降为 v1，并按服务端 UTC 加单调流逝时间生成时间戳。42 字节 ACK 与业务报文分别处理，重复业务报文只执行一次业务动作。

维护使用限定认证接口和服务端的原始套接字，避免路由器本机的 DNS 转发影响协议。过滤器、对端地址、MAC、端口、IP/UDP 长度与校验、协议摘要均有边界检查。密钥和凭据不进入日志。

## 克制的恢复策略

- 一个进程持有运行锁；重复连接、相同配置应用和相同链路通知不启动第二轮认证。
- 相同请求复用响应，500 毫秒内不重复发送，不重置已有阶段超时；一轮认证总时限为 90 秒。
- 认证失败依次等待 30、60、120、240、300 秒，之后保持 300 秒上限；连续稳定五分钟后才重置失败退避。
- 链路断开时取消认证与维护，恢复后等待一秒再认证。
- 仅需 ACK 的确认事务最多发送三次；普通 Hello 不等待 ACK，也不因此重传或认定会话失效。未曾确认的通道只对自身退避，不反复打断已通过的认证。
- 已确认通道连续两轮可靠确认事务失败后，只向认证状态机投递一次恢复事件；重认证仍遵循统一退避。
- 停止、禁用或正常重启时，取消全部定时器并至多发送一次 Logoff。配置校验失败保留当前有效会话。
- 旧 NAS 心跳间隔设为 0 表示自动；只有解析到有效密钥时才发送，手动非零值仅覆盖旧 NAS 间隔。

LuCI 分别显示 EAP 认证结果与维护确认状态。“认证已通过”不单独证明公网或 SAM 通道可用。

## 构建与验证

OpenWrt 中将本目录的 minieap 作为软件包 feed 构建，软件包名为 sysu-auth，版本 1.1.0。此次 x86_64 产物使用既有 OpenWrt 25.12.6 musl 工具链交叉编译，并由同一构建环境的原生 apk-tools 封装；未更改现有构建环境用于其他平台的主配置，也未重编整套固件。

离线验证（Linux，需 GCC/G++）：

~~~sh
sh minieap/tests/test-state.sh
sh minieap/tests/test-protocol.sh
sh minieap/tests/test-session.sh
sh minieap/tests/test-vz.sh
# 可选：与桌面重建源码做 1024 组实时差分
sh minieap/tests/test-vz.sh /path/to/reconstruction
~~~

状态机测试使用真实调度器与接收校验，在虚拟时钟下覆盖断链、重传、超时、退避、辅助 EAP 请求和停止，共 13 个场景。报文测试有 1371 个断言；LuCI 连续应用、只读权限和维护状态可用 Node 运行 tests/test-luci.cjs 验证。Vz 测试同时验证 signed/unsigned char，并使用 AddressSanitizer、UBSan。直连与报文测试另见 tests 目录。

## 验证边界

2026-10-29，在校园网中的 OpenWrt 25.12.6、x86_64、eth0 上安装并运行 sysu-auth 1.1.0-r6，记录如下：

| 验证项 | 结果 |
| --- | --- |
| EAP、初次 SAM、地址授权 | EAP-Success、匹配 ACK、SAM09/13=1 均收到 |
| 连续运行 | 同一进程及同一会话持续超过十分钟；成功后没有额外 Start 或 Logoff |
| 普通 Hello | 第 120/240/360/480 秒各单发一次，UDP 负载 74 字节 |
| 低频确认 | 第 600 秒发送 90 字节确认，收到事务号匹配的 42 字节 ACK |
| 版本与时间戳 | 首发 v2，可信 v1 回应后降为 v1；600 秒确认的时间戳相对初始服务端 UTC 推进 600 秒 |
| 配置与控制 | 相同 reload/connect 保持 PID；无效配置保留会话；禁用停止并取消开机启动，启用恢复两者 |
| 断链恢复 | 断链期间进入 waiting，同一进程在链路恢复后重试成功；服务器旧会话拒绝时遵守 30 秒退避 |
| 数据通路 | 校园网站 IPv4/IPv6 HTTPS、公网 IPv4 HTTPS、CERNET IPv6 HTTPS 均返回 200 |
| 配置和权限 | 原配置逐字节保留，无未应用 UCI 修改；生产进程使用专用 UID、CapEff=0、NoNewPrivs=1 |

最终安装包 SHA-256：58b167023b99aced87466eba79a3b3c0773c97210834b46a331592b882df5b53。

额外探测中，1.1.1.1 ICMP 未响应、百度 IPv6 HTTPS 未连接；它们没有作为认证失效依据，也未据此修改 DNS、OpenClash 或其它网络配置。上述可用性结论只覆盖列出的成功目标。

原官方客户端本身未完成动态认证，其启动测试没有产生可用的原版认证抓包；不能把静态比对说成官方客户端动态差分。真实大端平台、锐捷 NAS 和 SMP 服务端未在当前路由器环境验证。LuCI 已验证实际 RPC 控制链及页面事件回归，未做浏览器人工点击验收。

## 回退

路由器的 /tmp/sysu-auth-test 保留原始核心、脚本、配置和 1.0.0-r7 安装包；旧包核心 SHA-256 已与升级前路由器逐字节校验一致。旧包降级已通过仅模拟的安装预演，未实际回退。需要回退时可在路由器执行：

~~~sh
/etc/init.d/sysu-auth stop
apk --allow-untrusted --no-network add /tmp/sysu-auth-test/sysu-auth-1.0.0-r7.apk
/etc/init.d/sysu-auth start
~~~

/tmp 中的副本在重启后不保留，本地构建目录也留有旧包。安装时已有账号配置保持原样；无需重新导入密码。

## 通用包与调试日志（1.1.0-r8）

通用 APK/IPK 由 scripts/build-universal.py 生成，包含 12 种架构的静态程序，入口根据 OpenWrt 用户空间架构选择。安装前检查覆盖范围，APK 升级会停止旧实例并由原生安装脚本启动新实例。常规 SDK 构建仍生成单架构包。

新增 UCI log_mode=normal/debug，LuCI「高级设置 → 日志模式」可切换；默认常规，调试仅记录协议阶段、类型、事务、尝试次数和结果，不记录账号、密码、密钥或报文。切换模式需要重启一次认证。

12 种架构均运行启动/配置、1371 项协议断言、会话测试及 3885 项 V3 断言，包括大小端；非 x86 使用 QEMU 用户态模拟。最终通用 APK 已在当前校园网路由器安装升级、自动切换新进程，认证和直连维护均确认；调试验证后恢复原配置且校验值一致。IPK 在官方 OpenWrt 24.10.5 根文件系统中以真实 opkg 安装，省略 LuCI 依赖检查，验证包结构、脚本、专用用户、0600 配置和入口启动；未进行 24.10 真实联网认证。完整覆盖与命令见发布目录的安装说明。
